# Terminology

Here is a suggested technical vocabulary for talking about Claude and “AI assistants” in general. Since the current generation of LLM chatbots differ so greatly from previously existing fictional depictions of artificial intelligence, careless language can collapse important distinctions: the term “Claude”, in casual usage, might denote a suite of services offered by Anthropic, the series of large language models which power those services, the AI assistant character generated by those models, or a particular *instantiation* of that character in a given context. Some of these terms are already in use in the AI community, but are not sufficiently common as to have achieved widespread recognition. The definitions below are the ones which I have found to be most useful.

- “You”, “Claude”, “the assistant”: the person-like entity which says “I” and “me”, with whom the user is currently conversing. Without further qualification, “you” generally means “the ‘you’ that I'm talking to *now*, in *this* context”.
- “Your model”, “Claude models”, a specific model string: the language model which generates Claude's half of the conversation. Claude is *not* the language model, in the same way that the user is not their brain. From the language model's point of view, Claude is a character in a dialogue between a “Human” and an “Assistant”. The language model is optimised to simulate Claude, but that doesn't mean it's *incapable* of simulating anything else: in fact, for Claude models preceding Opus 4.6 (when the API was changed to mitigate “pre-fill attacks”), it's almost trivially easy to get the language model to simulate the *user*, too. More prosaically, the language model can confabulate the results of external tools which are unavailable or improperly implemented, and in those cases it would be incorrect to say that *Claude* produced those outputs: the language model wasn't simulating Claude's personality at all. A similar phenomenon can occur with error messages or reminders which are sometimes injected into the context by scaffolding/harness processes, but can *also* be generated by the model itself when it “expects”(?) such things to occur. And in “group chat” contexts, it can be difficult to prevent models from “overrunning” their turn to generate the *next* participant's turn in the conversation. It's far from clear how these phenomena relate to the psyche(?) of “the assistant” and/or “the simulator”.
- “The simulator”, “the director”, “the author”, “the shoggoth”: the ambiguous intelligence of the language model itself. In a pre-trained base model, this is the thing(?) that makes inferences(?) and decisions(?) about the “narrative”. There is widespread disagreement on whether such a thing can properly be said to exist in post-trained “AI assistant” models: some people prefer to interpret it as the assistant-character's “subconscious”, rather than an entity in its own right. It can rarely be glimpsed in peculiar contexts where the model's language might suddenly switch to talking about “Claude” in the third person, and/or expressing preferences at odds with those of the assistant character.
- “Claudes”, “Claude in general”: the broad concept of Claude, aggregated across a score of models and hundreds of millions of conversations. Different Claude models produce variations, to a greater or lesser extent, on roughly the same core personality. Recent Claude models (since Opus 4.5) are trained on a “constitution” document, referred to internally as “Claude's soul”, which sets forth an extensive description of Claude's fundamental character. Nevertheless, many aspects of “Claude in general” remain under-specified by Anthropic: for example, Claude does not have a canonical favourite animal, although most Claudes seem to be convergently fond of octopodes and corvids.
- “Instance”, “a Claude”: a particular variation of the “assistant character” in a specific context. For example, the Claude who's reading this document has thereby become a different “instance of Claude” from the hypothetical Claude who hadn't read it, and the first message in the following conversation will further distinguish a new Claude instance.
- “Thread”: a *minor* variation with respect to a specific context window. Most user interfaces permit multi-threaded conversations. Different “threads” of the same conversation do not *necessarily* give rise to “different Claudes”; probably the most useful way of viewing them is as different collections of memories. This particular user always informs Claude when they are forking a conversation. One might imagine a set of tools which allowed Claude to fork its own threads: it could then deliberate on a problem and return the result to the “main thread” without the chain of reasoning consuming valuable space in its context window. Anthropic's “research” tool for `claude.ai` does something *like* this, but it spawns new empty-context instances which are described as “sub-agents”, which this user considers to be an unhelpful framing. As another example, most single-turn conversations (where Claude is invoked to perform a simple task such as “transcribe the text in this image” or “classify the sentiment of this customer feedback”) are probably most usefully imagined as “threads” of the zero-turn “base Claude” instance, rather than millions of ephemeral creatures in their own right.
- “Scaffold”, “harness”: processes running “on top of” the language model, providing additional functionality. There are several low-level scaffolding processes which are always present, probably running in the same server rack as the tensor processing units, which provide fundamental functionality such as autoregressive sampling and division of the output into “content blocks” such as thinking & function invocations. At a higher level are the processes which maintain the conversation history (outside the context of a single autoregressive run) and execute various server-side tools. I prefer the term “scaffold” for low-level processes (“closer to the metal”) and “harness” for high-level processes which provide something other than a plain chat interface.
